> 状态：冲榜版 | 基于 Demo(vanilla-v2) 扩展 | 语言 Python 3.11+ 纯标准库

## 0. TL;DR

- **目标**：**冲击榜首**——全部得分模块拉满 + 对抗性策略压制对手，最大化 `score1(任务)+score2(击杀)+score3(生存)` 三项总和。
- **技术栈**：Python 纯标准库，零第三方依赖（确保判题器环境可直接运行，无需 pip）。
- **核心增量**：补全协议解析 → 跨回合记忆 → 经济/升级链 → 夜间战斗极致化 → 自进化任务系统（沙盒+LLM+SOP）→ 对抗压制（召唤令/视野/资源争夺）。
- **实施顺序**：全模块并行推进、无 P2 丢弃；生存分(score3)与击杀分(score2)打底，任务分(score1)与对抗策略拉开身位。

## 1. 目标与约束

### 1.1 得分公式分解

```
总分 = score1(任务) + score2(击杀) + score3(生存天数)
```

| 分项 | 上限(约) | 难度 | 模块 | 冲榜要求 |
|---|---|---|---|---|
| score3 生存 | 10+20+...+100 = 550 | 低 | economy/builder/combat | **必满**：基地 level3+多层围墙+武器前置，10 天 0 破 |
| score2 击杀 | 数百(随天数递增) | 中 | combat | **榨干**：锥形/穿透/溅射协同+道具 AOE+BOSS 优先 |
| score1 自进化任务 | 单任务数百×N | 高 | evolver | **决胜**：SOP 秒答赚速度加成+任务期 LLM 不计限榨干 |
| score1 推理(价格) | 经济增益间接转分 | 中 | economy | **必做**：每天新闻解析，涨价日卖矿+采集倾斜 |
| score1 长上下文宝藏 | 单次大额积分+金币 | 高 | treasure | **必做**：多天累积+LLM 推断+召唤迭代修正 |
| 对抗压制 | 压低对手得分 | 中 | adversary | **加分项**：召唤令骚扰+视野盲区+机器人引诱 |

**结论**：冲榜无短板——score3 必满(550)，score2 榨干(每夜清场)，score1 全做(自进化+推理+宝藏)，并叠加对抗策略压低对手实际分。

### 1.2 硬约束

| 约束 | 阈值 | 违反后果 |
|---|---|---|
| 单回合响应 | 5 秒（连接建立 10 秒） | 计 1 次异常 |
| 异常累计 | 5 次 | 该队停止调度直至比赛结束 |
| 参赛代码异常退出 | 不再拉起 | 直接出局 |
| 沙盒命令 | 15 秒 | 超时不计异常但任务失败 |
| LLM 调用 | 3 次/游戏日(130回合)，任务期间不计限 | 超限报 errorCode=5 |

### 1.3 关键机制理解

**异步工具调用模式**（最容易设计错的点）：

```
回合 N:   response.prompt="..." / response.executeCmd="..."   → 提交
回合 N+1: request.llmResp="..." / request.lastCmdResult="..."  → 拿结果
```

- LLM 与沙盒都在**判题器侧**执行，选手只负责组织 prompt/命令 + 下回合解析结果。
- 这意味着任何依赖工具结果的决策都有 **1 回合延迟**，必须用"请求-等待-消费"状态机管理，不能同步阻塞。
- 任务期间(executeCmd 仅任务期可用)LLM 不计限，是高价值窗口。

### 3.3 调度层 `brain.py`（重构）

```python
def decide(payload) -> Response:
    turn = Turn.load(payload)
    memory.update(turn)
    cmds = {}
    prompt = ""
    execute_cmd = ""

    try:
        with watchdog(4.5):  # 超时熔断
            if turn.is_day:
                # 昼：经济>建造>任务>宝藏(优先级递减)
                economy.run(turn, memory, cmds)
                builder.run(turn, memory, cmds)
                evolver.maybe_day(turn, memory, cmds)  # acceptTask/walk
                treasure.maybe(turn, memory, cmds)
            else:
                # 夜：战斗优先，任务期可继续沙盒探索
                combat.run(turn, memory, cmds)
                evolver.maybe_night(turn, memory, cmds)
        # 异步工具：在未占满动作的角色回合，填充 prompt/executeCmd
        prompt, execute_cmd = evolver.dispatch_tools(turn, memory)
    except TimeoutError:
        pass  # 保命：返回已构造的部分 cmds
    except Exception:
        pass  # 保命：返回已构造的部分 cmds

    return Response(cmds, prompt, execute_cmd)
```

**优先级裁决原则**：一个角色一回合只能一条指令。当多需求冲突时：
1. 自进化任务期内的开拓者 → 任务动作（最高，限时窗口宝贵）
2. 夜间角色 → 操控武器攻击
3. 白天工人 → 建造/升级 > 采集 > 卖买
4. 白天开拓者 → 任务 > 宝藏 > 协助经济

**经济循环**：采集 → 卖矿 → 买券 → 升级。

**升级优先级表**（金币有限时的消费顺序）：
1. 基地 level1→2 (100金, 血量1500→3000, 生存核心)
2. 武器升级券1×3 (100金/座, 射程+伤害提升)
3. 基地 level2→3 (150金)
4. 武器升级券2×3 (150金/座)
5. 围墙升级券 (低优, 围墙是耗材)

**价格推理（推理类任务）**：
- 建立"事件关键词→矿种→影响天数"规则表，如：
  - `塌方/停工/矿脉修复` + `铁` → 明后天铁价涨、不可采
  - `铜矿` + `罢工` → 铜价涨
- 在涨价日的**当天白天**卖对应矿石（明天才停工，今天还能采且涨价生效）
- 价格波动信息也驱动采集优先级：优先采涨价矿

**目标选择算法**（关键得分点）：

```python
def select_targets(turn, tower):
    reach = tower.range
    candidates = [r for r in turn.robots
                  if chebyshev(tower.pos, r.pos) <= reach
                  and r.health > 0 and r.abnormal_state != "dizzy"]
    if tower.kind == "gatling":
        # 多目标须落在90°锥内，选同方向集群
        return pick_cone_targets(candidates, tower.pos, tower.level)
    if tower.kind == "railgun":
        # 穿透：选弹道能穿最多的目标方向
        return [pick_pierce_target(candidates, tower.pos)]
    if tower.kind == "rocket":
        # 溅射：选密集聚类中心
        return pick_cluster_centers(candidates, tower.level)
```

**弹道计算**（加特林/电磁炮会被阻挡）：
- 用 Bresenham 算直线格，沿途找最近机器人作为命中点
- 电磁炮穿透：沿弹道逐格扣能量=min(剩余能量, 机器人血量)

**道具战术**：
- BOSS(800血) 出现 → 眩晕法宝控 5 回合 → 火箭+电磁集火
- 小型机器人群 → 范围炸弹(3×3, 100伤) 清场
- 召唤令骚扰对手：早期用小型召唤令(20金)给对方加压

### 3.7 长上下文宝藏 `treasure.py`

**流程**（多天累积）：

```
Day1..N: 累积 folkLegends 到 memory.folk_legend_log
         ↓ 每天用 LLM(prompt) 推断
DayM:    形成假设 {地点?, 物品?, 时间?}

           2=无宝藏/未到时间 → 调整时间/地点假设
           1=成功
```

### 3.8 自进化任务系统 `evolver.py`（大赛重点）

这是 score1 的大头，也是"Agent 自进化"的考察核心。

**任务状态机**：

```
IDLE → 寻路到任务点 → ACCEPTED → 探索(沙盒/LLM) → ANSWER_SUBMITTED → DONE/超时
                              ↑                      ↓ (失败/部分)
                              └── 重试(带SOP) ←──────┘
```

**沙盒执行器**（核心）：

```python
def dispatch_tools(turn, mem):
    # 1. 消费上回合结果
    if turn.last_cmd_result:
        result = parse_cmd_result(turn.last_cmd_result)  # "[exitCode:N]\n<输出>"
        mem.active_task.observe(result)
    if turn.llm_resp:
        mem.active_task.observe_llm(turn.llm_resp)

    # 2. 决定本回合提交什么
    task = mem.active_task
    if task and task.phase == "exploring":
        if need_shell(task):
            return "", gen_shell(task)       # executeCmd
        if need_llm(task) and mem.llm_budget_ok():
            return gen_llm_prompt(task), ""
    return "", ""
```

**SOP 沉淀与复用**（"自进化"精髓）：

```python
@dataclass
class SOP:
    task_signature: str      # 任务类型指纹(如"查询天气API")
    steps: list[Step]        # 通用步骤序列
    script: str              # 可复用的 shell/python 脚本
    api_template: dict       # 已知接口调用模板

# 任务1完成后：
sop = distill_sop(task1_observations)  # 从探索记录蒸馏SOP
mem.sop_library[task1.type] = sop

# 任务2..N 来时：
if task.type in mem.sop_library:
    sop = mem.sop_library[task.type]
    # 直接用 SOP 脚本执行，跳过探索，快速提交答案
    return sop.script
```

**示例（任务书 5.3）**：任务1查北京天气→形成"调天气API"的SOP；任务2查上海、任务3查广州→复用 SOP，直接 executeCmd 调同一 API 换城市参数，秒提交。

**LLM 预算管理**：
- 游戏日 3 次配额：2 次给自进化任务（理解任务+生成答案），1 次给宝藏推理
- 任务期间不计限 → 任务窗口内可多轮 LLM 探索，是高价值时段
- errorCode=5 时降级为纯沙盒探索

### 4.1 加特林锥形多目标选择

```python
def pick_cone_targets(robots, origin, level):
    if not robots: return []
    # 按相对 origin 的方向角分组
    groups = group_by_angle(robots, origin, half_cone=45)
    # 选机器人最多的一组，取 level 个
    best = max(groups, key=lambda g: sum_score(g))  # 优先高积分机器人
    return [r.pos for r in best[:level]]
```

### 4.2 电磁炮穿透弹道

```python
def railgun_damage(origin, target, robots, energy):
    cells = bresenham_line(origin, target)
    total = 0
    for cell in cells:
        hit = next((r for r in robots if r.pos==cell and r.health>0), None)
        if hit:
            dmg = min(energy, hit.health)
            total += dmg; energy -= dmg
            if energy <= 0: break
    return total  # 用于目标选择时的收益评估
```

```python

def do_POST(self):
    try:
        payload = json.loads(raw)
        response = decide(payload)              # 内部已 watchdog
    except Exception:
        response = EMPTY_RESPONSE               # 绝不返回格式错误
    self.write(json.dumps(response))

# brain.py
def decide(payload):
    try:
        with hard_timeout(4.5):                 # 硬熔断
            ...构建 cmds...
    except (Timeout, Exception):
        pass                                    # 返回已构造部分，不抛
    return Response(cmds or {}, "", "")         # 永远合法
```

**原则**：宁可不动作（空 roleCommandMap），也不返回非法格式/超时。5 次异常即退赛，保命优先于得分。

```python
def kill_score(robot, tower):
    base = {smallRobot:1, middleRobot:2, largeRobot:4, bossRobot:10}[robot.kind]
    # 优先秒杀(伤害>=血量)拿满积分
    if tower.can_one_shot(robot): base *= 2  # 杀得快价值高
    # BOSS 高分加成
    if robot.kind == bossRobot: base *= 3
    return base / chebyshev(tower.pos, robot.pos)  # 越近越优先
```

### 8.4 极致任务策略（score1 决胜）

**速度加成是冲榜最大杠杆**：
